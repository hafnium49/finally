## Findings

### P2 - independent-reviewer hook silently no-ops on fresh checkouts

`independent-reviewer/hooks/hooks.json:8` appends output to `planning/.hook-logs/codex-stop.log`, but the command does not create `planning/.hook-logs` first and that directory is not tracked. Shell redirection is opened before `codex exec` starts, so a fresh checkout fails before running the review command; the trailing `; exit 0` then hides the failure from Claude Code. Add `mkdir -p planning/.hook-logs &&` before `codex exec`, or redirect to an existing path as `.claude/settings.json` does with `/tmp/claude`.

### P2 - Empty ticker payloads still bypass the `invalid_ticker` contract

`backend/app/api/watchlist.py:45` and `backend/app/api/portfolio.py:56` still use `Field(..., min_length=1)`. That means `{"ticker": ""}` is rejected by Pydantic before `normalize_ticker()` runs, returning `{"error": "validation_error"}` instead of the contract-specified `invalid_ticker` for a ticker that fails the regex (`planning/API_CONTRACT.md:231`, `planning/API_CONTRACT.md:339`). I verified both `POST /api/watchlist` and `POST /api/portfolio/trade` return `validation_error` for an empty ticker. If the goal is for ticker-specific malformed values to share the same machine code, remove the Pydantic length guard and let `normalize_ticker()` own this validation too.
