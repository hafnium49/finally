# Review: changes since last commit

## Findings

1. **Low - FastAPI lifespan example is not runnable as written** (`planning/MARKET_INTERFACE.md:106`, `planning/MARKET_INTERFACE.md:116`, `planning/MARKET_INTERFACE.md:184`)

   The sample calls `await source.start(initial_tickers=["AAPL", "GOOGL", ...])`, and later says callers must `await source.start(initial_tickers)`, but the shipped interface is `start(tickers: list[str])` and does not define an `initial_tickers` keyword (`backend/app/market/interface.py:26`). The same snippet creates `cache` inside `lifespan()` and then references `cache` at module scope in `app.include_router(create_stream_router(cache))`, which would raise `NameError` if copied directly. Use `await source.start(["AAPL", "GOOGL", ...])` and either make the snippet explicitly pseudocode or restructure it so the router gets a cache that is actually in scope.

2. **Low - `PriceCache.remove()` version behavior is documented inconsistently** (`planning/MARKET_INTERFACE.md:159`, `planning/MARKET_INTERFACE.md:169`, `planning/MARKET_INTERFACE.md:318`)

   The version-counter section says both `update()` and `remove()` bump `version`, and the testing matrix says `test_cache.py` pins version advancement on `update`/`remove`. Later, the same document says `remove(ticker)` does not bump `version`. The latter matches the implementation: `PriceCache.remove()` only pops the ticker and does not increment `_version` (`backend/app/market/cache.py:59`). The tests also only assert version increments for `update()` (`backend/tests/market/test_cache.py:60`). Update the doc to make the removal/SSE behavior unambiguous.

3. **Low - Massive API doc claims SSE keepalives are implemented when they are still a gap** (`planning/MASSIVE_API.md:321`)

   `MASSIVE_API.md` says "The keepalive comment fires every 15 s", but `_generate_events()` currently emits only the initial `retry:` directive and price `data:` events when the cache version changes (`backend/app/market/stream.py:61`, `backend/app/market/stream.py:75`). `MARKET_INTERFACE.md` correctly calls keepalive comments a gap (`planning/MARKET_INTERFACE.md:238`). Reword the Massive doc to describe this as planned work, or implement timed keepalive comments in `stream.py`.

4. **Low - Massive package version wording conflicts with the locked project dependency** (`planning/MASSIVE_API.md:5`)

   The doc says the `massive` package is current as of May 2026 at `v2.7.0`, while this checkout is locked to `massive==2.2.0` (`backend/uv.lock:269`). Since the file is framed as reference documentation "as used in FinAlly" (`planning/MASSIVE_API.md:3`), readers may assume examples and attribute mappings were validated against the installed project version. Distinguish the upstream latest release from the locked FinAlly version, or update the lockfile if the newer SDK is required.
