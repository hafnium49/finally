# Review: changes since last commit

## Findings

1. **Low - FastAPI lifespan example is not runnable against the shipped interface** (`planning/MARKET_INTERFACE.md:106`, `planning/MARKET_INTERFACE.md:116`)

   The snippet calls `await source.start(initial_tickers=["AAPL", "GOOGL", ...])`, but the actual abstract method and implementations accept `start(tickers: list[str])` with no `initial_tickers` keyword (`backend/app/market/interface.py:26`). The same snippet creates `cache` inside `lifespan()` and then calls `app.include_router(create_stream_router(cache))` outside that scope, so copied as written it also fails with `NameError`.

   Suggested fix: either mark the block as pseudocode, or change it to an app-factory/module-scope cache pattern and call `await source.start(["AAPL", "GOOGL", ...])`.

2. **Low - `PriceCache.remove()` version behavior is documented two incompatible ways** (`planning/MARKET_INTERFACE.md:159`, `planning/MARKET_INTERFACE.md:169`, `planning/MARKET_INTERFACE.md:318`)

   The version-counter section says both `update()` and `remove()` bump `version`, and the test matrix says tests pin version advancement on `update`/`remove`. A few lines later the same doc says `remove(ticker)` does not bump `version`, which matches the shipped code: `PriceCache.remove()` only pops the ticker and never increments `_version` (`backend/app/market/cache.py:59`). This leaves readers unsure whether ticker removal should trigger SSE clients, and it describes test coverage that is not present in `backend/tests/market/test_cache.py`.

   Suggested fix: if silent removal is intentional, update the version-counter section and test matrix to say only `update()` advances `version`.

3. **Low - Keepalive behavior is described as active in one doc even though it is still missing** (`planning/MASSIVE_API.md:321`)

   `MASSIVE_API.md` says "The keepalive comment fires every 15 s", but `stream.py` only yields the initial `retry:` line and price `data:` events on version changes; there is no keepalive branch in `_generate_events()` (`backend/app/market/stream.py:61`). `MARKET_INTERFACE.md` correctly calls this out as a gap at `planning/MARKET_INTERFACE.md:238`, so the API doc now contradicts both the shipped code and the companion design doc.

   Suggested fix: reword the Massive doc to say keepalive comments should be added, or implement the keepalive behavior in `stream.py`.

4. **Low - Massive client version wording can mislead readers about the version FinAlly actually runs** (`planning/MASSIVE_API.md:5`)

   The doc says the `massive` package is current at `v2.7.0`, but this checkout is locked to `massive==2.2.0` (`backend/uv.lock:269`). The upstream latest-version note may be true, but the file is framed as reference documentation "as used in FinAlly", so readers may assume the examples and attributes were validated against the version installed by this project.

   Suggested fix: distinguish "latest upstream release" from "FinAlly locked version", or intentionally update the lockfile if the docs are meant to describe 2.7.0 behavior.
