# Review: changes since last commit

## Findings

1. **Low - FastAPI lifespan example is not copy-pasteable against the shipped interface** (`planning/MARKET_INTERFACE.md:106`)

   The lifecycle snippet calls `await source.start(initial_tickers=["AAPL", ...])`, but the `MarketDataSource.start` contract and both shipped implementations accept `start(tickers: list[str])`; they do not define an `initial_tickers` keyword. The same snippet calls `app.include_router(create_stream_router(cache))` outside the lifespan function where `cache` is local, so copied as written it would also fail with `NameError`.

   Suggested fix: either make the snippet explicitly pseudocode, or change it to a runnable pattern where the cache is created in module scope/app factory scope and `await source.start(["AAPL", "GOOGL", ...])` is called with the actual method signature.

2. **Low - `PriceCache.remove()` version behavior is documented two incompatible ways** (`planning/MARKET_INTERFACE.md:159`)

   The document first says both `update()` and `remove()` bump `version` by 1, and the testing matrix repeats that `test_cache.py` pins version advancement on `update`/`remove`. A few lines later it says `remove(ticker)` does not bump `version`, which matches the shipped `backend/app/market/cache.py` implementation. Readers will not know whether ticker removal is supposed to trigger SSE emission, and the test matrix describes coverage that does not exist.

   Suggested fix: keep the "silent removal" behavior documented if that is intentional, and update the earlier version-counter paragraph plus the testing matrix to say only `update()` advances the version.

3. **Low - Dependency version wording can mislead readers about the version FinAlly actually runs** (`planning/MASSIVE_API.md:5`)

   The document says the `massive` package is current at `v2.7.0`, but the checked-in backend lockfile resolves `massive==2.2.0` (`backend/uv.lock:269`). The upstream statement appears accurate for the latest public release, but the doc is framed as the API reference "as used in FinAlly", so readers may assume local behavior and examples were validated against 2.7.0 when this checkout runs 2.2.0.

   Suggested fix: distinguish "latest upstream release" from "FinAlly locked version", or update the lockfile intentionally if the doc is meant to describe 2.7.0 behavior.
