# Review: changes since last commit

## Findings

1. **Low - `PriceCache.remove()` version behavior is documented two incompatible ways** (`planning/MARKET_INTERFACE.md:159`, `planning/MARKET_INTERFACE.md:169`, `planning/MARKET_INTERFACE.md:318`)

   The version-counter section says both `update()` and `remove()` bump `version` by 1, and the test matrix says `test_cache.py` pins version advancement on `update`/`remove`. A few lines later, the same document says `remove(ticker)` does not bump `version`. The latter matches the shipped implementation: `PriceCache.remove()` only pops the ticker and does not increment `_version` (`backend/app/market/cache.py:59`). The current tests also only assert version increments on `update()` calls (`backend/tests/market/test_cache.py:60`). This leaves future implementers unsure whether ticker removal should trigger SSE clients.

   Suggested fix: if silent removal is intentional, update the version-counter section and test matrix to say only `update()` advances `version`.

2. **Low - `MASSIVE_API.md` claims SSE keepalive behavior that the shipped stream does not implement** (`planning/MASSIVE_API.md:321`)

   The Massive API reference says "The keepalive comment fires every 15 s", but `_generate_events()` currently yields only the initial `retry:` directive and price `data:` events when `price_cache.version` changes (`backend/app/market/stream.py:61`, `backend/app/market/stream.py:75`). There is no idle keepalive branch. `MARKET_INTERFACE.md` correctly calls this out as a gap (`planning/MARKET_INTERFACE.md:238`), so the two new docs contradict each other and the shipped code.

   Suggested fix: reword `MASSIVE_API.md` to say keepalive comments are still planned, or implement timed keepalive emission in `stream.py`.

3. **Low - Massive package version wording can mislead readers about what FinAlly actually runs** (`planning/MASSIVE_API.md:5`)

   The doc says the `massive` package is current at `v2.7.0`, but this checkout is locked to `massive==2.2.0` (`backend/uv.lock:269`). The upstream latest-version note may be true, but the file is framed as reference documentation "as used in FinAlly", so readers may assume the examples and attribute names were validated against the installed project version.

   Suggested fix: distinguish "latest upstream release" from "FinAlly locked version", or intentionally update the lockfile if the docs are meant to describe 2.7.0 behavior.
