## Findings

### P1 - SSE route test still hangs before the new timeout can run

`backend/tests/api/test_market_routes.py:88` still enters `async with client.stream("GET", "/api/stream/prices")` before the new `asyncio.wait_for` at line 97 is reached. With the installed `httpx` ASGI transport, `handle_async_request()` awaits the ASGI app to finish and buffers response body parts before returning the `Response`; because `/api/stream/prices` is an infinite `StreamingResponse`, the context manager never enters and the timeout around `chunk_iter.__anext__()` cannot fire. I confirmed the single test still hung until killed. This keeps the route test capable of wedging the suite/CI despite the new timeout. Test `_generate_events()` directly with a fake disconnected request, add a test-only finite stream path, or wrap the entire stream entry in a timeout that actually covers response acquisition.

### P2 - independent-reviewer hook cannot start in a fresh checkout

`independent-reviewer/hooks/hooks.json:8` redirects the hook output to `planning/.hook-logs/codex-stop.log`, but the command does not create `planning/.hook-logs` and that directory is not present in this checkout. Shell redirection is opened before `codex exec` starts, so the command fails with `cannot create planning/.hook-logs/codex-stop.log: Directory nonexistent`; the trailing `; exit 0` then hides the failure from Claude Code. As shipped, the plugin's only Stop hook will silently skip the independent review unless the user manually creates the log directory first. Add `mkdir -p planning/.hook-logs &&` before `codex exec`, or redirect to an existing directory as `.claude/settings.json` now does for `/tmp/claude`.
